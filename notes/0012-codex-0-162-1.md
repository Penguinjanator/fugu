Codex is now pinned to 0.162.1

Fugu now targets Codex 0.162.1. The launcher will offer to switch your Codex to it, and your existing Fugu configs and API key carry over unchanged.

This spans several upstream releases (0.155 through 0.162): the interface is now fullscreen by default (switch modes with /tui), with transcript search, mouse selection, copy-on-select and /copy for transcript blocks; there are new terminal themes with Mermaid diagram and equation rendering, clickable links in prompts and banners, and new sessions open on a compact welcome screen. Sending a message while a response is streaming now interrupts it and continues with your new input; to keep the old behaviour of waiting for the response to finish, add "instant_interrupt = false" under [features] in ~/.codex/config.toml. Codex also keeps streamed answers when a turn fails or is interrupted, waits as long as the server advises when it is rate-limited, fixes resume and fork history, and asks for approval by default before sending terminal input to commands running with elevated permissions.

Nothing is required on your part, and your Fugu models and settings work as before. Four settings are added for Fugu in ~/.codex/fugu.config.toml: the shared background server's automatic start is pinned off ("daemon_auto_start = false"), since a Fugu session runs on its own and would otherwise show a startup warning on every launch; voice conversations are pinned off ("realtime_conversation = false"), since the Fugu API does not offer realtime voice; worktrees stay off ("worktrees = false"), as they were for Fugu sessions before, since they would now also add a set of local worktree tools to every request of an interactive session (launch with "codex-fugu --enable worktrees" to use them); and Codex's one-time screen-reader check is marked done ("screen_reader_detection_done = true" under [tui]), so Codex no longer rewrites that file on first launch. If you use a screen reader, add "animations = false" under [tui] in ~/.codex/config.toml to turn TUI animations off. Remote plugins and unbounded connection retries stay pinned off as before.
